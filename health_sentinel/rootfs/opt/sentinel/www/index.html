Core responsiveness

Latency of a real request through to Core's event loop. A rising line here is the classic signature in the minutes before a hang.

Memory pressure (PSI)

Share of time tasks spent stalled waiting for memory. Unlike "RAM used", this rising is what precedes an OOM kill.

Incidents

Every gap in service the sentinel observed or reconstructed. Click one to open its report.

Multi-integration outages

Several unrelated integrations losing entities within the same couple of minutes points at a shared cause — the network, DNS or power — rather than at any one device. Entities that have been dead a long time are excluded, so a restart does not look like an outage.

Integration health

Standing problems

Entities that have been unavailable long enough to count as broken rather than blipping. These are excluded from outage detection.

Serial devices

Zigbee and Z-Wave coordinators live here. One of these disappearing unavailables everything behind it.

Network interfaces

Link state, addresses and connectivity. Traffic counters are not shown: they are namespaced per container, and reading the host's would need privileges this add-on deliberately does not take.

Kernel & hardware events

OOM kills, machine check errors, filesystem faults, USB drops — read live from the host journal.

Containers

Sorted by memory. A positive growth figure means the container is using more memory than it was an hour ago — that is a leak.
